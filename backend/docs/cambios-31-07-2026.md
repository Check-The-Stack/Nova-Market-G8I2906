## 🚀 Resumen de Nuevas Características e Integraciones

En esta sesión de desarrollo se completaron funcionalidades clave, se alinearon rutas del contrato de API y se agregaron medidas de seguridad y escalabilidad al catálogo y sistema de compras.

### 1. Endpoint Dinámico de Categorías (`GET /api/categories`)
*   **Propósito:** Proveer al frontend un listado dinámico de las categorías de productos que existen en la base de datos, evitando hardcodearlas del lado del cliente.
*   **Implementación:**
    *   Controlador: [categoryController.ts](file:///c:/Users/vikdu/OneDrive/Escritorio/Nova-Market-G8I2906/backend/src/controllers/categoryController.ts)
    *   Rutas: [categoryRoutes.ts](file:///c:/Users/vikdu/OneDrive/Escritorio/Nova-Market-G8I2906/backend/src/routes/categoryRoutes.ts)
    *   **Lógica:** Realiza una consulta `distinct` con Prisma en la tabla `Product` sobre la columna `category` para traer los valores actuales en tiempo real.
*   **Endpoint:** `GET /api/categories` (Acceso público)

### 2. Paginación y Límites en Catálogo de Productos (`GET /api/products`)
*   **Propósito:** Mejorar el rendimiento de carga y la escalabilidad del catálogo de cara al crecimiento de inventario.
*   **Implementación:**
    *   Archivo modificado: [productController.ts](file:///c:/Users/vikdu/OneDrive/Escritorio/Nova-Market-G8I2906/backend/src/controllers/productController.ts)
    *   **Lógica:** Soporta opcionalmente los query params `page` y `limit`. Al recibirlos, calcula dinámicamente `skip` y `take` de Prisma, devolviendo tanto la porción de productos correspondiente como metadatos de paginación (`total`, `page`, `limit`, `totalPages`).
    *   **Compatibilidad:** Si el frontend no envía estos parámetros, el endpoint devuelve el catálogo completo de manera normal, garantizando retrocompatibilidad con las pantallas actuales.
*   **Endpoint:** `GET /api/products?page=1&limit=10`

### 3. Endpoint de Detalle de un Pedido por ID (`GET /api/orders/:id`)
*   **Propósito:** Permitir al frontend y a los clientes ver el recibo/detalle completo de una compra efectuada.
*   **Implementación:**
    *   Controlador: [orderController.ts](file:///c:/Users/vikdu/OneDrive/Escritorio/Nova-Market-G8I2906/backend/src/controllers/orderController.ts)
    *   Rutas: [orderRoutes.ts](file:///c:/Users/vikdu/OneDrive/Escritorio/Nova-Market-G8I2906/backend/src/routes/orderRoutes.ts)
    *   **Capa de Seguridad (Autorización):** Se implementó una regla donde un cliente autenticado (`customer`) solo puede visualizar pedidos cuyo `userId` coincida con el suyo. Si se trata de un administrador (`admin`), se otorga acceso de lectura total a cualquier pedido solicitado.
*   **Endpoint:** `GET /api/orders/:id` (Acceso protegido mediante JWT)

### 4. Reestructuración y Alineación de Rutas de Pedidos
*   **Propósito:** Ajustar los endpoints del backend al contrato de comunicación definido previamente en las especificaciones técnicas (`02-endpoints-api.md`).
*   **Cambios:**
    *   Se reubicaron las rutas del cliente común a la raíz del enrutador de órdenes.
    *   Se creó un enrutador de administración dedicado ([adminRoutes.ts](file:///c:/Users/vikdu/OneDrive/Escritorio/Nova-Market-G8I2906/backend/src/routes/adminRoutes.ts)) para centralizar la gestión administrativa de forma aislada y más segura.
*   **Comparativa de Rutas:**
    *   **Mis Pedidos:** Antes `/api/orders/my-orders` ➡️ **Ahora `GET /api/orders`**
    *   **Pedidos Generales (Admin):** Antes `/api/orders/admin` ➡️ **Ahora `GET /api/admin/orders`**
